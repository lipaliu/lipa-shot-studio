# A + B + D · 故事板改版

2026-10-14 用户选择：A 的视觉、B 的机位图、D 的故事板。组合已经实现；最终视觉仍待用户评审。

## 来源与实现边界

- A [OpenFrame](https://github.com/kazim-45/openframe)：采用炭黑工作底色、暖金强调、单镜头分区的视觉方向。
- B [Open Shot Designer](https://github.com/koosoli/OpenShotDesigner)：采用俯视人物、机位朝向、轴线、光位及道具关系图的交互概念。
- D [Storyboarder](https://github.com/wonderunit/storyboarder)：采用当前镜头大画面、镜头手记、底部顺序镜头条的故事板结构。

本轮在现有 React 项目内独立实现，没有复制这三项第三方源码、图片、图标或字体。研究阶段的真实截图在项目外的本地选型页中；其许可不冒充本项目整体许可。

## 已实现

主界面保持左侧剧本、右侧结果。默认故事板，可切换原有完整分镜表。故事板中再切换画面与机位图；镜头条、上一镜/下一镜、状态、秒数和手记联动。完整文本仍在编辑抽屉中，支持复制提示词、审核与导出。

机位图使用自有 SVG 组件。相机、目标、人物、主光和已有道具可拖动；键盘方向键或坐标框也可调整。人物支持添加、改名、删除。坐标范围 5–95，为相对场地位置，非测量尺寸。前两位人物之间的虚线只是对话轴线参考，不是自动越轴判定。草图修改会写入提示词，但不自动改写摄影文字；需人工复核一致性。

每镜可上传不超过 2 MB 的 PNG/JPEG/WebP，保存后作为故事板画面展示，支持替换与移除。数据与项目一起保存在服务端 SQLite，完整 JSON 导出包含图片。未上传图片时为程序绘制的占位构图，明确标注“构图示意 · 非生成画面”；没有新增付费生图接口，不声称生成了电影分镜插画。

未保存时切镜、换视图、换筛选或打开另一个项目会被阻止，提示先保存或撤销；刷新/关闭页面触发浏览器未保存提示。图像/机位修改按现有规则恢复待审，并使已有的整场 AI 审阅失效。

## 模型与存储

- `blocking`：actors、camera（含 targetX/targetY）、light、props、note。Schema 校验坐标、长度及数量上限。
- `storyboardImage`：可选 raster data URL；拒绝 SVG/远程 URL，限制长度。传入模型的整场审阅数据会剔除图像字符串。
- 新任务的摄影阶段合同要求输出 blocking，并保持同场坐标一致；旧项目无需迁移，缺少草图时显示“创建机位草图”。
- mock 流程与 HTTP 保存已验证，真实 GPT/豆包的空间推断、坐标一致性及生成质量仍待程序员实测。不要把配置状态当成模型连通验证。

## VI 与验证

背景 #141513，面板 #1c1e1a，强调 #d5b56f，主字 #eae6dd，辅助字 #b3b4a9。系统中文字体，正文 14–16 px，元信息不低于 12 px。圆角用于工具与分区，金色只强调当前镜头、选项和主操作；状态颜色独立。
