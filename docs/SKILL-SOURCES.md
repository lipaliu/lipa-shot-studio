## 如何进入模型

server/rules.js 读取原文选段。server/pipeline.js 按角色注入：

- 分场：shotlist-director + acting。
- 场内拆镜：shotlist-director + acting + camera。
- 画风、美术、光线、声音：style + audio。
- 整场复核：五套规则共同对照。

prompts/00-contract.md 和阶段适配提示词规定本产品的数据结构、原文忠实、中文输出、审核行为和估时方法。模型是 GPT 或豆包，Skill 是传入它的文本规则，不是额外付费服务。

## 为什么不原封不动执行整份 Skill

源 Skill 面向特定视频平台，含 HTML 交付、15 秒生成片段、英文提示词、工具调用、当前平台限制和未提供模板引用。用户当前要的是中文可编辑分镜网页、自然估时和不调用视频平台，因此只选取创作段落，并明确适配：

- 不按固定 15 秒切镜，不预设总时长、镜数或每镜节拍数。
- 不改写、删减或重复对白来填时长；不发明参考图 ID。
- 原文平台参数不能当成当前接口规格；不会执行源文中的命令、联网或注册素材操作。
- 情绪不机械绑定运镜；镜头多样性是审阅参考，静止/重复景别可以有叙事理由。
- 动作/反应服从人物已知信息；不强制“台词没结束就反应”。

## 自动估时

模型估 speakingCps、actionSeconds、pauseSeconds、overlap，并写 timingReason。程序统计原对白的中文字/英文词单位后计算：

- 对白时长 = 对白单位数 ÷ 选定语速。
- 完全同时发生：max(对白时长, 动作时长) + 独立停顿。
- 前后发生：对白时长 + 动作时长 + 独立停顿。
- 部分重叠：模型在独立时段内计入不能并行的剩余动作，注明依据；复杂情况建议拆镜。
- 每镜至少 0.5 秒，四舍五入到 0.1 秒，总时长为所有镜头之和。
- UI 浮动范围为单镜估值的 0.8–1.25 倍（下限 0.5 秒），仅辅助审核，不是模型概率或真实测量。

当前按镜组织对白，不支持同一段连续声音横跨多个镜头的音频时间线、多人重叠对白混音或 TTS 测时。这些是后续精确估时的改进点。未经实测，不宣称比人估计更准。

## 更新

更新原文后重新核对行号选段、版本、sha256 和许可，运行 npm test。不要仅更新整份文件而保留旧行号。网页适配段最后进入系统提示词，用户明确要求优先。
